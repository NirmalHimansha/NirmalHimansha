Privacy Policy

Data protection and privacy practices for the Apocalypse Survival Shorts automated YouTube Shorts generation pipeline.

Last Updated: November 23, 2026 Version: 1.1 Effective Date: November 23, 2026
🔓 Public Access — No Login Required: This privacy policy is publicly accessible at https://www.nirmal.cc/apocalypse-shorts-privacy.html without any login, authentication, cookies, tracking, or paywall. It can be viewed by anyone at any time. The application homepage at https://www.nirmal.cc/apocalypse-shorts.html is also publicly accessible without authentication.

1. Introduction & Scope

Apocalypse Survival Shorts ("the Application", "we", "our") is an open-source automation pipeline that generates and publishes daily YouTube Shorts about post-apocalyptic survival scenarios. This Privacy Policy explains what data the Application processes, how it is used, where it is stored, and your rights as the operator.

Critical Clarification: This Application is a personal automation tool run by a single content creator on their own hardware. It does not serve the public, does not have user accounts, does not collect data from viewers or website visitors, and does not process any personal information from third parties. The only "user" is the creator who operates the pipeline.

The Application name "Apocalypse Survival Shorts" matches exactly the name configured in the Google Cloud Console OAuth consent screen and the YouTube channel branding (@NirmalHimansha).

AI Content Safety Compliance: This Application does not generate, facilitate, or enable the creation of non-consensual intimate imagery (NCII), child sexual abuse material (CSAM), sexual content, deepfakes of real individuals, or any prohibited content under Google's AI Safety policies. All generated content is strictly educational survival material covering 10 predefined post-apocalyptic themes (zombie survival, nuclear aftermath, wilderness skills, etc.). The LLM prompts are hardcoded templates with no user input; the video generation uses Stable Video Diffusion with fixed survival-themed visual prompts.

3. Third-Party API Data Flows

The Application communicates with the following external services only for their stated purposes. Each service has its own privacy policy governing data they receive.

3.1 Google (YouTube Data API v3 & OAuth 2.0)

  • Data Sent: OAuth tokens (access/refresh), video file (MP4), title, description, tags, category, privacy status.
  • Purpose: Authenticate the creator's YouTube channel and upload generated videos as Shorts.
  • Google's Privacy Policy: https://policies.google.com/privacy
  • User Control: Creator can revoke access anytime at Google Account Permissions.

3.2 Replicate (AI Video Generation)

  • Data Sent: Text prompt (visual description derived from script), model parameters (FPS, motion bucket, etc.).
  • Purpose: Generate AI video clips using Stable Video Diffusion model.
  • Replicate's Privacy Policy: https://replicate.com/privacy
  • Data Retention: Per Replicate's policy; creator can delete predictions via Replicate dashboard.

3.3 Telegram (Bot API)

  • Data Sent: Bot token (auth), chat ID (target), message text (video URL, title, timestamp).
  • Purpose: Send private notification to creator when upload completes.
  • Telegram's Privacy Policy: https://telegram.org/privacy
  • User Control: Creator can delete bot via @BotFather or block the bot.

3.4 Local LLM Service (Custom/OpenAI-Compatible)

  • Data Sent: Prompt (script template + theme), generation parameters (temperature, max_tokens).
  • Endpoint: http://127.0.0.1:31415/v1 (localhost only — no external network traffic).
  • Purpose: Generate unique narration scripts locally.
  • Data Retention: Depends on local LLM service configuration; typically no persistence.
No Other Third Parties: The Application does not use analytics, tracking, advertising, CDN, crash reporting, or any other third-party services. No data is sent to the Application developers.

6. Data Security

  • Local Storage: All credentials and data stored in local files with OS filesystem permissions (not in source code, not in version control).
  • Transport Security: All external API communication uses HTTPS/TLS 1.2+.
  • Authentication: OAuth 2.0 with refresh tokens (no password storage); API keys in Authorization headers.
  • Local LLM Isolation: Runs on 127.0.0.1:31415 — no external network exposure.
  • No Database Exposure: SQLite database is local file only, no network listener.
  • Secrets Management: config.yaml, client_secret.json, token.json are in .gitignore and never committed.

7. Your Rights (As the Creator/Operator)

Since you are the sole operator of this Application, you have full control:

  • Access: All data is in your local project directory — open any file.
  • Rectification: Edit config.yaml or any local file at any time.
  • Erasure: Delete any file, rotate any API key, revoke OAuth access.
  • Portability: Export scripts (Markdown), videos (MP4), database (SQLite .dump).
  • Restriction: Stop the scheduler (Ctrl+C), disable API keys.
  • Objection: Uninstall the Application; delete the directory.

For third-party data (Google, Replicate, Telegram), exercise rights via their respective dashboards/policies linked in Section 3.

8. Children's Privacy (COPPA / GDPR Article 8)

The Application is not directed at children under 13 (or 16 in EU). It does not knowingly collect, process, or store any personal data from children. The generated content is educational survival material for general audiences. The YouTube channel may be marked "Made for Kids" or not at the creator's discretion in YouTube Studio — this Application does not control that setting.

9. International Data Transfers

API calls may route through servers in multiple countries:

  • Google/YouTube: Global infrastructure (US, EU, Asia) per Google Cloud Compliance.
  • Replicate: US-based infrastructure per their privacy policy.
  • Telegram: Distributed infrastructure per Telegram Privacy Policy.
  • Local LLM: No international transfer — runs on creator's laptop.

By using the Application, the creator acknowledges and accepts these transfers.

13. Deployment & Verification Guide for Google OAuth

To complete Google OAuth verification, the following steps must be completed:

13.1 Domain Ownership Verification (Required)

  1. Go to Google Search Console
  2. Add property: https://www.nirmal.cc (URL prefix)
  3. Verify ownership via HTML file upload, DNS TXT record, or Google Analytics
  4. Wait for verification to propagate (up to 24 hours)

13.2 Google Cloud Console OAuth Consent Screen Updates (Required)

  1. Go to Google Cloud Console → APIs & Services → OAuth consent screen
  2. App Name: Change from "claude" to exactly "Apocalypse Survival Shorts"
  3. User Support Email: nirmalhimansha@gmail.com
  4. App Domain: Add nirmal.cc to Authorized domains
  5. Homepage URL: https://www.nirmal.cc/apocalypse-shorts.html
  6. Privacy Policy URL: https://www.nirmal.cc/apocalypse-shorts-privacy.html
  7. User Type: Change from "Internal" to "External"
  8. Test Users: Add nirmalhimansha@gmail.com as test user
  9. Save and submit for verification

13.3 Deployment to www.nirmal.cc (Required)

These pages must be deployed to https://www.nirmal.cc/ with HTTPS:

  • Homepage: https://www.nirmal.cc/apocalypse-shorts.html
  • Privacy Policy: https://www.nirmal.cc/apocalypse-shorts-privacy.html

Deploy using your existing hosting (GitHub Pages, Netlify, Vercel, or current provider). Ensure the v=2 cache-busting query strings on CSS/JS are preserved.

13.4 Wait Period

After deploying and updating Google Cloud Console, wait 24–48 hours for Google's systems to crawl the updated pages before resubmitting for verification.

13.5 Verification Submission

In Google Cloud Console OAuth consent screen, click "Submit for Verification". Select scopes: .../auth/youtube.upload, .../auth/youtube, .../auth/userinfo.email, .../auth/userinfo.profile. Provide justification: "Personal automation tool for daily YouTube Shorts generation. Single-user application run by content creator on own hardware. Publicly documented at provided URLs."
